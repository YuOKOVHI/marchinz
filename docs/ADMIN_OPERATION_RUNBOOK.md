# MarchinZ 管理者運用ランブック

最終更新: 2026-05-06

## 目的

管理者機能（通報対応・凍結対応・権限付与）を、安全かつ一貫した手順で運用するための実務ガイドです。

## 想定ロール

- **管理者**: `#moderation` の閲覧・対応が可能
- **一般ユーザー**: 管理者機能は不可

## 本実装仕様（確定）

- 認証方式は Firebase Authentication の Google 認証を使用する。
- 管理者判定は `auth-config.js` の `adminEmails` に含まれるメールアドレスで行う。
- 非管理者が `#moderation` に直接アクセスした場合は `#top` に戻す。
- ログアウト時は `auth.signOut()` を実行し、ヘッダー/ドロワーのユーザー UI を即時にゲスト UI へ戻す。
- BAN（凍結）は `mll_profiles/{uid}.banned=true` で制御する。ログイン時に確認し、凍結中はサインアウトして利用不可メッセージを表示する。
- 退会（削除）は「確認 -> Google 再認証 -> 個人データ削除 -> Auth ユーザー削除」の順で実行する。
- 退会後も運用上残すデータ（イベント情報、掲示板投稿など）は残置する。
- 新規登録の同意メッセージは初期非表示。`MarchinZ に登録する` 押下時に未同意なら表示する。

## 管理者権限の付与/解除

### 付与

1. 対象ユーザーの Google メールアドレスを確認する。
2. `auth-config.js` の `adminEmails` にメールアドレスを追加する。
3. デプロイ後、対象ユーザーに再ログインしてもらい `#moderation` が表示されることを確認する。
4. 付与履歴（日時・実施者・理由）を運用メモに記録する。

### 解除

1. `auth-config.js` の `adminEmails` から対象メールアドレスを削除する。
2. デプロイ後、当該ユーザーに再ログインを依頼し、権限が消えていることを確認する。
3. 解除履歴（日時・実施者・理由）を記録する。

## 通報対応フロー（#moderation）

1. **一次確認**
   - 通報対象（投稿/コメント）と通報理由を確認する。
   - 明らかな違反か、追加確認が必要かを判定する。
2. **判断**
   - 軽微: 投稿修正依頼または経過観察
   - 中程度: 非表示対応
   - 重度: 非表示 + アカウント凍結検討
3. **実施**
   - 必要な操作を管理画面で実行する。
4. **記録**
   - 対応内容・日時・担当者を残す。

## 凍結（banned）対応

### 凍結実施

1. `mll_profiles/{uid}.banned = true` を設定する。
2. 該当ユーザーのログイン後挙動（利用不可表示）を確認する。
3. 対応理由を記録する。

### 凍結解除

1. `mll_profiles/{uid}.banned = false` に戻す。
2. ログイン・投稿可否を再確認する。
3. 解除理由を記録する。

## 退会（withdrawn）ユーザー対応

- `withdrawn=true` のユーザーは通常機能を制限する。
- 問い合わせ対応時は、退会処理の完了状態を確認して案内する。

## インシデント時の基本方針

- 事象の切り分けを優先し、即時に影響範囲を特定する
- 強い措置（凍結・一括非表示）は記録を残して実施する
- 暫定対応後に恒久対応をチケット化する

## 運用ログ記録

- 実施履歴は `docs/ADMIN_OPERATION_LOG_TEMPLATE.md` をコピーして記録する。
- スプレッドシート運用時は `docs/ADMIN_OPERATION_LOG_SHEET_COLUMNS.md` の列定義を使用する。
- 最低限「実施日時・実施者・対象UID・操作内容・理由・結果」は必須で残す。
