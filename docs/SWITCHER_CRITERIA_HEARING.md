# 自動スイッチング 基準ヒアリングシート（DCI配信ディレクター回答版）

2026-08-04。空欄だったヒアリングシートに、DCI配信ディレクターとして回答を入れた版。

各項目に **【状態】** を付けてある。

```
実装済み   このセッションで入れた。QAの見張りつき
実装可能   いま持っている材料で入れられる。指示があれば入れる
要タグ     カメラに情報を付けてもらう必要がある（UIの追加が要る）
要検出     新しい映像解析が要る（重い。iPhoneの負荷と相談）
優さん判断 過去の指示と正面から当たる。決めてもらう必要がある
```

---

## 0. いちばん大事な原則

> **音楽を追うのではなく、音楽より先に座る。それが中継です。**

自動編集が素人くさく見える理由はほぼ1つで、**起きたことに反応している**から。
中継は「これから起きること」を知っていて、その前に画を用意する。
以下の回答は全部この原則から出ている。

---

## 1. いま入っている基準（2026-08-04 時点・更新済み）

**使えない画を捨てる（絶対条件・上から順に判定）**

- 急パン／激ブレ（グローバル動き 0.28超）
- 手ブレ（カメラ自身のブレ 0.11超）
- フォーカス外れ（鮮鋭度が中央値の30%未満）
- カメラを振っている（方向のそろった動きが50%超）
- 人が写っていない（顔0＋動き0.12未満＋前後も静か）

**残った中から点数で選ぶ**

| 材料 | 中身 |
|---|---|
| ショット種 | 寄り＝顔が大きい／グループ＝3〜10人／引き＝顔が小さい |
| 音の性格 | ソロ・ソリ／バッテリー／ピット／**全奏（音量×厚み）**／静か |
| カメラの性格 | 操作カメラ（据わった絵を加点）／俯瞰固定 +0.15／**出番を控えるカメラ −0.40** |
| 人の指定 | 役割タグ（引き・寄り・ピット）／出番の希望（少なめ・おまかせ・多め） |
| 画質 | 鮮鋭度がクリップ中央値より高いと加点 |
| 交互化 | 直前 −0.90／2つ前 −0.25／出番が空くほど最大 +0.48 |
| **ジャンプカット防止** | **直前と画角・人数がほぼ同じカメラへは最大 −0.55** |

**引きに限定するハード規則**

- 全奏（tutti 0.7以上）
- 衝撃の2拍前（音圧の急上昇を先読み）
- サリュート直後の1カット目
- **楽章・セクションの切れ目**
- 一定間隔（おすすめなら3ショットに1回）

**出番の保証**

- 4ショット出ていないカメラを強制的に出す（ソロ中は2ショットまで待つ）
- **出番を控えるカメラは間隔を倍の8ショットに**（DM・フロントピット・「少なめ」指定）
- 同じカメラの連続オンエアは5秒まで（おすすめの場合）

**ショット長**

- 引き 4〜6秒／寄り 2〜4秒（おすすめの場合。レベルでスケール）

## 2. 回答

### A. カメラの位置関係

#### Q1. 撮影位置の種類は？

**回答【要タグ】** 5種類で足りる。DCIの中継もこの粒度。

```
高所正面（プレスボックス）  ドリルの形が読める唯一の位置。基準になる画
低所正面（フロア・50yd）    表情と迫力。寄りの主役
サイド                      奥行きが出る。フロントの流れを見せる
エンドゾーン                向かってくる／去っていく。移動が最も伝わる
ピット付き                  フロントアンサンブル専用
```

> **なぜ位置が要るか**: いま「同じ側の2台を続けて切る」ことを止められない。
> これは自動編集がいちばん素人くさく見える瞬間で、
> 見ている人には「切り替わっていない」ようにしか見えない。

#### Q2. 気持ち悪い組み合わせは？

**回答**

```
【絶対】高所正面 → 低所正面 の直結
        同じ方向から寄っただけ。画角が変わっただけで「切った」意味がない
        間に必ずサイドかエンドを挟む

【絶対】サイド → 反対側のサイド
        軸越え。隊列の進行方向が画面上で逆転して、見ている人が迷子になる

【なるべく】エンドゾーン → エンドゾーン（反対側）
        向かってくる絵から去っていく絵へ飛ぶ。同じ隊形とは思えなくなる
```

#### Q3. 気持ちいい流れは？

**回答**

```
高所正面（形を見せる） → サイド（奥行き） → 低所正面（表情） → 高所正面（戻る）
この4手が基本。「広い→深い→近い→広い」の呼吸

エンドゾーンは移動の瞬間にだけ挿す。定常では使わない
```

#### Q4. イマジナリーラインは守るべき？

**回答【実装可能・簡易版は実装済み】** **守る。ただしマーチング固有の解釈で。**

フィールドの長辺（50ydライン）が軸。正面側とサイドは同じ空間として読めるが、
**反対側のサイドへ飛ぶと隊列の進行方向が反転する**。ここだけは絶対。

> **【実装済み】** 位置タグが無いいまは、代わりに **画の似かたで代用**している。
> 直前と画角・人数がほぼ同じカメラへ切ると減点（最大 −0.55）。
> 「同じ側の2台」は画も似るので、これでかなり防げる。
> 実測: そっくり同士の切り替えが 9回 → 1回。
> **本式（位置タグ）にすれば軸越えを正確に止められる。**

### B. フィールドで何が起きているか

#### Q5. カンパニーフロントのとき

**回答【一部実装済み】**

```
【絶対】高所正面の引き。サイドは使わない
        カンパニーフロントは「横一線に並んでいること」が価値。
        サイドから撮ると重なって、ただの塊にしか見えない
【絶対】6〜8秒は動かさない。読ませる時間が要る
【絶対】ヒットの2拍前には座っている
```

> **【実装済み】** 全奏（tutti 0.7以上）は引きに限定。衝撃の2拍前に着席。
> 引きは4〜6秒。
> **【要タグ】** 「高所正面の」は位置タグが無いのでまだ効かせられない。
> **【優さん判断】** 6〜8秒は「4秒以上は同じのにしない」と当たる（§3-④）。

#### Q6. ドリルが大きく展開する瞬間

**回答【要検出】**

```
【絶対】展開の最中は切らない。1つの画で見せ切る
        散る・集まるは「動きの連続」が価値。途中で切ると何が起きたか分からない
【なるべく】展開が終わって形が決まった瞬間に、そこで初めて切る
```

> 音では取れない。画面全体の動きベクトルの発散／収束を見れば取れるが、
> いまの解析（3秒ホップ）では粗すぎる。**新規の映像解析が要る。**

#### Q7. 「この形が出たら絶対にこう」

**回答**

```
【絶対】ソリスト1人がフィールド前面に出てくる → 低所正面の寄り
【絶対】カラーガードだけのフィーチャー → 引き（１人を追わない。面で見せる）
【絶対】バッテリーが横一線でフロントに来る → 高所正面の引き
【なるべく】ピットのマレットソロ → ピット付きカメラの寄り
```

> **【実装済み】** ピット区間はピット役のカメラへ +1.2。
> それ以外は形の検出が要る（**要検出**）。

### C. ショウの構造

#### Q8. 楽章・セクションが変わる瞬間

**回答【実装済み】** **必ず一度引きでリセットする。**

```
【絶対】切れ目ちょうどにカットを置き、そこは引き
        寄りのまま通過すると、見ている人は「まだ同じ場面」だと思い続ける。
        ショウは複数の楽章で、切れ目は場面転換そのもの
```

> **【実装済み】** 音だけから2つの手がかりで検出する。
> ① 静けさの谷（1.2秒以上）から戻った瞬間
> ② 局所テンポが18%以上変わった瞬間
> 検出したら、直前のショットをそこまで伸ばしてカットを置き、引きに限定する。

#### Q9. 曲の頭と終わり

**回答【一部実装済み】**

```
【絶対】ドラムメジャーは頭と終わりだけ。途中で抜くと間延びする
【絶対】サリュート直後の1カット目は全景。セットの全体像を先に見せる
【絶対】最後の1音は引き。全員が写っていないと終わった気がしない
```

> **【実装済み】** サリュート直後の全景。演奏前はDMの寄りを最優先。
> **【要タグ】** 「DMは頭と終わりだけ」は、DM役のタグが要る。
> いまは寄りスコアで拾っているだけなので、途中でも出てしまう。
> **【実装可能】** 「最後の1音は引き」は musicEnd を持っているので入れられる。

#### Q10. バラード／ロック／クローザー

**回答【一部実装済み】**

```
バラード     長いショット（6〜8秒）／ディゾルブ1.5〜2秒／寄り主体
             人の表情と音の余韻を見せる場面。切り替えは邪魔
ロック       短いショット（2〜3秒）／カットのみ／引きと寄りを交互
             リズムに乗せる。ディゾルブは絶対に使わない
クローザー   前半は短く煽り、最後のインパクトで引きに座って止める
             だんだん短く → 最後だけ長く、が定石
```

> **【実装済み】** 静か／低BPMでディゾルブ1.0〜2.0秒。音圧とテンポでショット長が伸縮。
> **【実装可能】** 「クローザーはだんだん短く」は、演奏終了までの残り時間から作れる。

### D. 見せたいものが画に入っているか

#### Q11. ソロのとき、どのカメラを優先？

**回答【一部実装済み】**

```
【絶対】バッテリーのソロ → 前から。後ろからはスティックしか見えない
【絶対】ホーンのソロ → 低所正面の寄り。ベルの向きが正面を向く
【なるべく】ピットのソロ → ピット付き。無ければ高所正面の引きで逃げる
```

> **【実装済み】** ソロ・ソリでは寄りを強く優先（wClose = 0.30+0.95×feature）、
> 操作カメラの据わった絵を大きく加点。
> **【要タグ】** 「前から／後ろから」は位置タグが要る。

#### Q12. ソリストが画角にいるか分からないとき

**回答【実装可能】** **引きへ逃げる。**

```
【絶対】確信が持てないなら寄らない
        「ソロなのに関係ない人の顔がアップ」は、
        「ソロなのに引き」より100倍かっこ悪い。
        引きなら少なくとも嘘をついていない
```

> **【実装可能】** いまは逆で、ソロだと分かると寄りを強く押している。
> 「そのカメラに人が1人だけ大きく写っている（nF=1 かつ maxF が大きい）」を
> 確信の条件にして、満たさないなら寄りの加点を切る、という形で入れられる。

#### Q12-b. 対象のドリル・MMがない固定カメラ ★2026-08-04 追加指示

**回答【実装済み】** ドラムメジャー・フロントピットは**その場で動く**が、
画面の中を移動しない。ドリルを撮っているカメラは隊列が画面を横切る。
この違いを「動くセルが毎回おなじか」で見分け、出番を控える。

> **【実装済み】** 6×4=24セルのうち「4分の1以上のサンプルで動いた」セルの数
> （hotCells）が8以下なら「その場で動くだけ」。
> 減点 −0.40 に加えて、**飢餓ガードの間隔を4→8ショットに伸ばす**。
>
> ★ 減点だけでは足りなかった: 飢餓ガードは採点を無視して4ショットごとに
> 強制的に出すので、2026-08-03 に −0.40 を入れて以来、出番の**回数**は
> まったく変わっていなかった。
>
> 実測（3カメラ・29カット）: 素のまま9回 → 控えめ4回。**出番ゼロにはしない**。
>
> ★ しきい値8/24は合成素材で決めた値。書き出しログに
> 「出番を控えるカメラ … 動くセルN/24」を出すので、実素材で詰められる。

#### Q13. パート別の決まりごと

**回答**

```
バッテリー   横の並びが価値。引き〜グループ。1人に寄らない
ピット       手元が価値。寄り。全体を撮っても何も伝わらない
ホーン       ベルの向きが価値。正面から。サイドからは音が見えない
カラーガード 面で見せる。1人を追うのは投げ上げの瞬間だけ
```

> **【要検出】** パートの識別は楽器検出が要る。重い。優先度は低い。

## 3. 弱点への回答

```
① tutti は音圧そのもの → 【実装済み】分ける必要がある。
   フォルテのソロが全奏と同じ点になり、いちばん寄りで見せたい聴かせどころを
   引きにしていた。厚みは調波性(harm)で見分ける ─ 単独楽器は自己相関の
   ピークが高く、多数の音程＋打楽器が重なるほど下がる。
   tutti = 音圧 × (1 − 0.5×調波性)
   実測: フル(音圧.95/調波.30)=0.81 → 引きに限定
         フォルテのソロ(音圧.95/調波.80)=0.57 → 限定しない

② ソリストがフレームに入っているか → 【優先度: 中】楽器検出は要らない。
   Q12の「確信が持てないなら寄らない」で9割は防げる。
   楽器検出（要検出・重い）は最後でいい。

③ 衝撃のしきい値が合成音基準 → 【実装済み・実素材待ち】
   書き出しログに「衝撃N箇所」を出してある。実素材で数を見てほしい。
   8分半のショウなら 15〜25箇所が妥当。極端に多ければ IMPACT_RISE を上げる。

④ 引きは4〜6秒か4〜8秒か → 【優さん判断】
   ディレクターとしては **カンパニーフロントだけ6〜8秒**が正しい。
   ただし「4秒以上は同じのにしない」（2026-08-03 優さん指示）と正面から当たる。
   折衷案: 全奏で引きに限定した回だけ上限を8秒へ、それ以外は4〜6秒のまま。
   → やるかどうかの判断がほしい

⑤ ディゾルブは局所BPMと静かさだけ → 【実装可能】
   楽章の切れ目を取れるようになった（回答C）ので、
   「バラード楽章の中だけディゾルブ」に絞れる。
   いまは静かならどこでもディゾルブなので、ロックの一瞬の静寂でも溶ける。

⑥ カメラの空間関係 → 【要タグ】回答A。位置タグ5種類。
   簡易版（画の似かたで代用）は実装済み。本式は位置タグを入れてから。

⑦ ソロ中でも「同じカメラは5秒まで」 → 【優さん判断】
   ディレクターとしては **ソロは8秒まで許すべき**。抜き画を見せ切れない。
   ただし④と同じく「4秒以上は同じのにしない」と当たる。
   ★ソロ中の出番の割り込み（飢餓ガード）を待たせる手当ては実装済みなので、
     いま最悪の状態ではない。

⑧ カット点は必ず拍・小節に乗る → 【現状で正しい】
   マーチングは小節頭で切るのが基本。フレーズ末で切りたいのは
   バラードのリタルダンドくらいで、そこはディゾルブが受け持っている。
   変える必要は薄い。
```

## 5. 補足

- 「絶対」と書いたものはハード規則（候補をそこに限定）にしている／する
- 「なるべく」は点数の加減点
- 現行の全仕様は `docs/SWITCHER_AUTOCUT_ALGORITHM.md`
- **【優さん判断】が2件（④⑦）ある。** どちらも
  「4秒以上は同じのにしない」との衝突。決めてもらえれば入れる
