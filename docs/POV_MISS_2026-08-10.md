# POV動画の取りこぼし（2026-08-10）— 原因と再発予防

## 何が起きたか

2026-08-10 20:50（コミット `d6e37da`）に POV カテゴリを新設し、30本を収録した。
その直後、**同じ Bluecoats 2026 Victory Run のヘッドカムが2本、収録から漏れていた**ことが判明した。

| video_id | 題名 | チャンネル | 公開（JST） | 収録 |
|---|---|---|---|---|
| `FQfM-hTy3uA` | Bluecoats 2026 "Gravity & Grace" **Lead Trumpet** Cam - Victory Run | Curzy | 08-09 | ✅ 入っていた |
| `0_eeiZoTLYY` | Bluecoats 2026 - Victory Run - **Lead Mellophone** Cam | Noah Arst | **08-10 09:17** | ❌ 漏れ |
| `7y2sDQ-Lmg4` | Bluecoats 2026 **Trumpet Screamer** Cam - Victory Run | jack zirkelbach | 08-10 | ❌ 漏れ |

**「新着だったから」では説明できない。** `0_eeiZoTLYY` は収録作業（20:50）の
**11時間半前**にはもう公開されていた。取りこぼしである。

## 原因

### 主因: POV だけ取り込みスクリプトが無く、母集団が定義されていなかった

4つのソースのうち、POV 以外の3つは「特定のチャンネルを全件なめる」スクリプトを持つ。
**母集団が閉じている**ので、走らせれば漏れない。

| ソース | 取り込みスクリプト | 母集団 | 採用規則 |
|---|---|---|---|
| マーチング祭 | `build_data.py` | @marching-matsuri | チャンネル全件 |
| DrumcorpsfunTV | `import_drumcorpsfun_dcj_all_japan.py` | @DrumcorpsfunTV | チャンネル全件 |
| FloMarching (DCI) | `import_flomarching_dci_full_shows.py` | @FloMarching | 10分以上 かつ `FULL SHOW`（題名/サムネOCR） |
| **POV** | **無し（手作業）** | **YouTube 全体** | 5分以上・奏者視点 |

POV は「検索して目についたものを拾う」運用だった。**検索順位に依存し、再現性がゼロ**。
同じ作業を明日やっても同じ結果にならない。

### 副因: 投稿者の多くが個人チャンネルである

上の3本は**すべて別々の個人チャンネル**から上がっている。
奏者本人が自分のヘッドカムを1〜3本だけ上げるのが普通で、
「POVを配信するチャンネル」という母体が存在しない。

このため、**既知チャンネルを列挙する方式は原理的に効かない**。
実測でも、収録済み30本のチャンネル21件を全件なめても `Noah Arst` には到達しない
（CSVに1本も無いチャンネルだから）。

### 副因: タイトルだけを見ていた

個人投稿はタイトルが素っ気ないことがあり（"Victory Run 2026" だけ等）、
楽器名やヘッドカムであることが**概要欄にしか書かれていない**場合がある。

## 再発予防

### 1. `scout_pov_videos.py` を新設（母集団を機械で作る）

```
        ┌──────────── 母集団を3軸で作る ────────────┐
  軸1 検索    団体 × カメラ語 を掛け合わせて横断検索
              （CSVに1本も無いチャンネルへ到達する唯一の軸）
  軸2 雪だるま 本判定を通った投稿者の最新20本を列挙
              （個人chは数本しかないので安い）
  軸3 再訪    CSV収録済みチャンネルを毎回全件列挙（新着に追随）
        └────────────────────────────────────┘
                          ↓
        ┌───── 判定：題名 ＋ 概要欄 の両方を読む ─────┐
          採る: POV語（pov/headcam/gopro/視点…）
                または 楽器語 × カメラ語
          落とす: 固定・編集カメラ（catwalk / overhead /
                  multi-cam / wide-angle / drone / react…）
          落とす: 5分未満
        └────────────────────────────────────┘
                          ↓
        ┌────── 台帳 pov_ledger.json ──────┐
          accepted / rejected を video_id で記録
          再実行しても既決は候補に出ない
          ＝ 判断が積み上がり、毎回見直さなくて済む
        └──────────────────────────────┘
```

使い方は `docs/OPS_GUIDE.md` の「POV（プレイヤー視点）を追加する場合」を見ること。

### 2. `test_scout_pov_videos.py` で判定を見張る（23件）

**取りこぼした3本を回帰試験として埋め込んだ。この3本を落とす変更は入れられない。**

歯があることは変異試験で確認済み:

| 変異 | 結果 |
|---|---|
| 概要欄を無視するようにする | FAIL（2件）✅ |
| 尺の下限を撤廃する | FAIL（1件）✅ |
| `multicam` の除外を消す | FAIL ✅ |
| `catwalk` / `overhead` / `drone` / `wide-angle` の除外を消す | それぞれ FAIL ✅ |

> ⚠️ 初版の試験は骨抜きだった。除外の試験文に楽器語が無く、
> 除外規則を踏む前に「手掛かりなし」で落ちていたため、
> `multicam` の除外を消しても PASS してしまった。
> **落とすべき試験文には必ず楽器語を入れる**（そうしないと規則を一度も踏まない）。
> 試験が落ちたときに試験の方を書き換えない。
