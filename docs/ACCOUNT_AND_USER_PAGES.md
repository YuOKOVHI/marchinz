# MarchinZ — アカウント・ユーザープロフィール・設定（サイト方針メモ）

サイト全体の仕様の一覧は **`docs/MARCHINZ_SPEC.md`** を参照してください。

本ドキュメントは、利用者・運営双方が「ログイン後の UI がどこで何をしているか」を共有するための整理です。**利用規約・プライバシーポリシーとは別レイヤーの実装説明**であり、文言の拘束力はサイト上の規約類を正とします。

## 認証・アカウント単位

1. MarchinZ のサインインは **Firebase Authentication の Google アカウント連携**を前提とする（構成は `auth-config.js`）。
2. 「利用規約およびプライバシーポリシーへの同意」は **`#signup`／`#login` の専用画面**および**機能別モーダル（例：コミュニティの初回投稿）**で案内する。グローバルヘッダー直下には登録フォームを置かない。
3. 公開サービス側のユーザー表示名・アイコンは **Firestore の `mll_profiles`（`/mll_profiles/{uid}`）**を主ソースとする。初回ログイン時に Firebase の表示名・アバター画像 URL をベースにドキュメントをマージ作成する。
4. **管理者**は `auth-config.js` の `adminEmails` に登録されたメール（Auth の実メール）で判定される。画面上はヘッダー表示名を「管理者」に差し替え、通報管理等の `data-admin-only` リンクを開示する。他ユーザーの **`#profile?uid=…`** を開いたときのみ、**アカウント凍結（BAN）**用のパネル（`#prof-admin-ban-panel`）が表示され、`mll_profiles` の `banned` / `banned_at` / `banned_reason` を更新できる（`user-profile-page.js`）。
5. **凍結**されたユーザーが Google でログインした場合、`auth.js` がプロフィールを読み **`signOut`** し、「利用規約により凍結」の旨をアラートする。Firestore では **`requesterCanAct()`**（退会していないかつ凍結されていないこと）により、凍結ユーザーの **書き込み**が拒否される。
6. **退会**の利用者向け文言・データ処理の根拠は、下記 **「退会仕様」** を正とする（実装は `auth.js` の退会ハンドラ）。

## 退会仕様（利用者向け・実装の根拠）

### 利用者向け（設定モーダル・完了モーダル・確認ダイアログと一致）

| 区分 | 内容 |
|------|------|
| **削除されるもの** | プロフィール表示に使う画像・各所へアップロードした画像（Storage）、Log日記（`mll_profiles/{uid}/event_log_diaries`）、Marching Life Log（`mll_logs` の当該 `user_id`）、マイリスト（`video_bookmarks` / `channel_bookmarks` / `video_lists`）、端末の MLL ローカル下書き（`localStorage` の `marchinz_mll_logs_v1` 等） |
| **サイト上に残る場合があるもの** | 作成したイベント（`mll_calendar_events` とその `attendees` 等）、掲示板の投稿（`mll_community_posts`）。投稿本文は残り、添付画像の Storage 実体は上記で削除されるため **画像だけ壊れる** 場合がある |
| **連携** | Google 再認証のあと **Firebase Auth のユーザー削除**により連携解除。同じ Google で再ログインすると **新しい UID** の別ユーザーとして扱われる |
| **退会後に残る Firestore** | 上記「残る」データに加え、掲示板・イベントの作成者名解決のため **`mll_profiles/{uid}` を `withdrawn: true` の参照用行として残す**（表示名は「退会ユーザー」等に置き換え。任意フィールドは `FieldValue.delete` で除去） |

### 実装上の注意

- 処理順: **Storage 削除 → 本人サブコレクション／`mll_logs` 削除 → `mll_profiles` を退会用マージ更新 → `currentUser.delete()`**。途中失敗時はエラー表示と `signOut()` がありうる。
- Firestore ルールの **`requesterCanAct()`**（退会・凍結のいずれでもないこと）により、退会または凍結後の当該 UID からの **新規投稿等は拒否**。
- 通報コレクション（`mll_community_reports`）はルール上クライアントから削除不可のため、退会フローでは消さない（運用で必要ならバックエンド対応）。

## ログイン後の UI（共通）

### ヘッダー右上

- **ログアウト中**: 「ログイン」「はじめての方」（従来どおり）。
- **ログイン済み**: **プロフィール画像・表示名**を常時表示し、隣に **ハンバーガーボタン**でメニューを開く。
  - **プロフィール編集**: 表示名・アイコン URL を編集するモーダル（`profile-form`）。
  - **設定**: 説明文とともに **アカウント削除（退会）**を配置する別モーダル。
  - **ログアウト**: Firebase からサインアウトし、状態をサイト全体へ `mll-auth-changed` で通知する。

Firebase が未構成のときはログイン関連ボタンを無効化し、ヘッダーへ短いヒント文言を表示する。

## 「ユーザーページ」に相当する体験

専用の `#user` SPA ページはなく、次のような **コンテキスト埋め込みのプロフィール表示**が「他者のユーザー画面」に相当する。

- **Marching Life Log（TOP／`#mll`）**: 自分のログ・他人のログから遷移し、一覧内で **ユーザー ID に紐づく公開プロフィール**（`mll-profile-viewer`）を読む。
- **イベント一覧・参加表**: 作成者／参加者のアイコン・名前クリックなどでプロフィール解決があり、Firestore の `mll_profiles` とキャッシュを参照する実装になりうる。
- **コミュニティ掲示板**: 投稿者名・アバターは投稿ドキュメント＋プロフィール補足で組み立てる。

いずれの画面でも **閲覧中のコンテンツとは独立して、ログイン済みならヘッダーに「自分」のメニュー**が残る設計である（ユーザー詳細ビューを開いたときだけメニューを消さない）。

## Firestore と責務の目安（実装側）

| 項目 | 主なフィールド／コレクション |
|------|-------------------------------|
| 認証 | Firebase Auth UID |
| 公開プロフィール | `mll_profiles`：`display_name`, `avatar_url`, `withdrawn`, **`banned`**, `banned_at`, `banned_reason` 等 |
| MLL | `mll_logs` とプロフィールの参照 |
| イベント | `mll_calendar_events` と `attendees` サブコレクション等 |
| 掲示板 | `mll_community_posts`、通報コレクション |
| Storage | 画像はルール済みパスへの投稿者 UID 単位のアップロード |

## メンテ時のチェックリスト

1. `#login`／`#signup` でログイン／同意フローが完結すること。
2. ログイン後、ヘッダーに自分の名前・画像が出て、ハンバーガーから **編集・設定（退会）・ログアウト**が操作できること。
3. `#mll` で他ユーザー参照 UI がヘッダーと干渉しないこと。
4. `auth-config.js` 未設定時に誤ってログイン済み状態にならず、明示的なヒントが出ること。
