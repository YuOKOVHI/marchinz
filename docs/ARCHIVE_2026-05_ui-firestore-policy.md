# アーカイブ（2026-05）：コミュニティ UI・イベント登録・Firestore 方針

本書は、当時の検討・実装の要点を後から追えるようにまとめた記録です。**運用の正**はリポジトリのコードと `firebase/firestore.rules` です。

## 方針決定（現状維持）

- **2026-05 時点**：イベント登録まわりの問題は **実用上解消**しているとの判断。
- **Cloud Functions + Admin SDK によるサーバー経由書き込み（いわゆる A 案 Phase 1）** は **採用しない**。当面は **Firestore Web SDK のクライアント直書き**を続ける。
- 別途議論されていた **Safari 系での Web SDK 不安定性対策**についても、現状問題なしなら **追加のインフラ変更は行わない**。

## 実装側で入った主な変更（アーカイブ対象の範囲）

### UI（演奏会等・掲示板）

- YouTube ページのカテゴリタブ行（`youtube-tabs` + `mz-tab-strip-yamap` + `youtube-tab-btn`）を ** canonical** とし、以下を同型に統一した。
  - 演奏会・大会・イベントの種別フィルタ（`data-cal-kind` は維持）
  - 掲示板一覧フィルタ（`data-community-filter` は維持）
  - 掲示板投稿フォームのカテゴリ（`data-community-form-theme` は維持）
- **「イベントを登録」**：種別タブの **下** に配置。**左右中央**・**タブとの余白**を確保。**団体一覧表示**ボタンと同系のオレンジ（`browse-inline-trigger`）。
- **掲示板「投稿する」**：同じオレンジ系・**中央寄せ**。タブとの余白を演奏会側に近づけた。

### イベント登録の技術経路（参照用）

- **`calendar-events.js`**（演奏会等パネルのフォーム）：`mll_calendar_events` へ `add`。タイムアウト race は無し。
- **`mll.js`**（Log 保存と同時にカレンダーへ書く経路）：約 **8 秒**の `Promise.race` で打ち切り。タイムアウト / `unavailable` 時は広告ブロック等の案内。

### Firestore

- クライアントペイロードと `firestore.rules` の `mll_calendar_events` create/update は、`kind` が **`演奏会` / `大会` / `イベント`** のみ（旧 **`マーチング関連`** は廃止）。

## 将来見直しのトリガー（メモ）

次のいずれかが再発した場合のみ、**Functions 経由書き込み**や **読み取り API** を再検討する。

- Safari（および類似環境）で **書き込みが再び不安定**／長時間ハングが再現する。
- **読み込み**経路まで含めて Web SDK が信頼できないことが確認される。

## 版番との対応

- 本アーカイブをリポジトリに取り込んだコミット／デプロイ単位で **`data-mz-version` をマイナー更新**（例：`1.11.x` → `1.12.0`）した。
