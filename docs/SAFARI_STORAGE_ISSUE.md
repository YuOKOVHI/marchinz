# iPhone Safari「書類とデータ」膨張問題 — 現状と引き継ぎ

最終更新: 2026-08-07 / 対象: MarchinZ Switcher（映像ツール群）/ 本番 v2.3.0 (Beta)

**この問題はまだ解決していません。** 対策の半分は入っていますが、残り半分は
「サイト側のコードからは消せない」ことが実測で分かっています。
Codexで続きをやる人は、まずこの文書を最後まで読んでから手を動かしてください。

---

## 1. 症状

iPhoneの Safari が使う容量（設定 → 一般 → iPhoneストレージ → Safari → **書類とデータ**）が
数GB〜10GB超まで膨らみ、優さんの端末の空き容量を圧迫する。

**厄介なのは、iOSのサイト別「Webサイトデータ」一覧に出てこないこと。**
`marchinz.netlify.app` の行は 6.6MB のままなのに、本体の「書類とデータ」だけが
11GB を超えていた（2026-08-06 実機で確認）。だから「どのサイトが犯人か」を
iOSの画面からは特定できない。

---

## 2. 原因（実機で2種類の混合と判明）

2026-08-06 に優さんのiPhoneで、2段階に分けて切り分けた結果:

```
書類とデータの膨張 = ① 取り込みの一時コピー  +  ② OPFSの蓄積
                     （セッション性・消せない）  （永続・消せる）
```

### ① 取り込み時に WebKit が作る内部コピー ← **サイト側から消せない**

`<input type="file">` で動画を選ぶと、**WebKitがその動画を内部にコピーする**。
これはブラウザの実装であって、JavaScript からは触れない。

- **実測**: 素材3本（約3GB）を選んで分析中の画面で **10.29GB → 13.84GB（+3.55GB）**。
  書き出しは1回もしていない状態での増加
- **Safariを完全終了すると解放される**（13.95GB → 分析中17.5GB → 終了で復帰を実測）
- `clip.file` はページ再読み込みで消えるため、素材の再選択が必須（`tools/switcher/js/state.js`）。
  つまり**リロードのたびに再コピーが起きる**
- 優さんの判断で、**この件の案内はユーザーに出していない**

### ② OPFS（Origin Private File System）の蓄積 ← 対策済み・消せる

書き出した完成品と、分割書き出しのパーツが `mz-export` ディレクトリに積もっていた。

- **Safariを終了しても、iPhoneを再起動しても消えない**（実機で11.26GBを確認）
- これが「消せない11GB」の主体だった
- 積もった原因は2つ:
  - 書き出しを繰り返すと前回ぶんが手放されない
  - 別シーン・別設定で作り直す導線が `releaseOpfs` を呼ばない
  - 起動時掃除の「6時間据え置き窓」が、古くないファイルを守り続けた

## 3. 実施済みの対策（すべて本番投入済み）

| 版 | 内容 |
|---|---|
| v1.109.0 | 退出時にOPFSを即解放 / 旧ジョブのパーツを即掃除 / サイト保存量の診断表示 / `pagehide` での sweep |
| v1.109.1 | レビュー反映（ガードの穴・古い診断値・掃除の取りこぼし） |
| v1.110.2 | OPFS掃除の欠陥修正（他の修正と同梱） |
| v1.113.3 | **書き出し開始時に前回ぶんを必ず手放す** |
| v1.113.4 | **起動時掃除を2段構えへ**（下記） |
| v1.113.5 | 深い掃除の取りこぼしと消しすぎを両方塞ぐ（レビューP1×2） |
| v1.113.6 | **掃除が probe 待ちで止まる真因を修正**（下記） |

### 3-1. 起動時の「深い掃除」（`tools/switcher/js/exporter.js` の `opfsSweep`）

```
Web Locks を ifAvailable で取りにいく
  ├ "mz-export"        … どのタブも書き出していないか
  └ "mz-export-result" … 未保存の完成品を持つタブがいないか
        ↓
   両方取れた = 誰も使っていない
        ↓
   据え置き窓を無視して全消し
   （残すのは「今セッションの成果物」と「現行ジョブの再開パーツ6時間以内」だけ）

   片方でも取れなかった回 → 従来の6時間窓に落とす（保守的モード）
```

**効果**: Switcher を開いた瞬間に、溜まっていたOPFSが消える。

`mz-export-result` を条件に足した理由は、**書き出し完了〜「動画を保存」の間は
`mz-export` を誰も持っていない**ため。その隙に別タブを開くと、深い掃除が
未保存の完成品を消してしまっていた（v1.113.5 で発見・修正）。

### 3-2. 掃除を probe から切り離した（v1.113.6・3度目の対策）

以前は `probeOpfs()`（Workerを起こしてOPFSに実際に書けるか実測する）の
`.then()` に掃除をぶら下げていた。**probeOpfs にはタイムアウトが無く**、
iOS Safari で Worker が応答しないと `.then` が永遠に来ない
= **11GBを消したい当の起動で、掃除が1バイトも走らない**。

いまは両者を独立に走らせている（`tools/switcher/js/app.js` 86〜92行）。
掃除に必要なのは main thread の `getDirectory` / `entries` / `removeEntry` だけで、
Worker は要らない。

### 3-3. 縮小版（プロキシ）は持ち越さない

`pagehide` で `MC.proxy.disposeAll()` を呼ぶ。縮小版は引き当てに元の `File` が要るが、
`File` は再読み込みをまたいで生き残らないため、持ち越す意味がない。
取りこぼしても次回起動の掃除が据え置き窓を無視して必ず消す。

### 3-4. ユーザーが自分で消せる導線

`tools/switcher/js/ui.js` の `renderStorageNote()`（2575行付近）。
OPFSに **300MB以上**（`MC.ui.PURGE_MIN_BYTES = 300e6`）残っていると出る:

> **この端末に、作った動画のデータが ◯GB 残っています**
> 保存ずみなら消して大丈夫です。iPhoneの空き容量が戻ります。 　[消す]

「消す」は `MC.exporter.purgeAll()`。書き出し中は `busy` を返して拒否する。

### 3-5. 切り分け用の診断

`MC.exporter.estLine()`（`navigator.storage.estimate()` の結果）を
書き出し後の診断ログ（`#eoStats`）と `errorLog` に出している。

**読み方**: ここ（サイト枠）が小さいのに本体の「書類とデータ」が大きければ、
犯人は ①取り込みコピー。ここが大きければ ②OPFSの蓄積。

## 4. まだ残っていること（Codexでやること）

### 最優先: そもそも対策が効いているかが**実機で未確認**

v1.113.4〜.6 の掃除は、**優さんのiPhoneで一度も検証できていません。**
まずここを確かめないと、次の設計判断ができません。

**測り方（優さんに1操作だけ頼む）**

```
1. 設定 → 一般 → iPhoneストレージ → Safari →「書類とデータ」の数値を控える
2. Safari を完全終了する（アプリスイッチャーで上スワイプ）
3. Safari で https://marchinz.netlify.app/tools/switcher/?tool=switcher を開くだけ
   （素材は1本も選ばない。ここが肝 — 選ぶと①のコピーが増えて測定が濁る）
4. 15秒ほど待ってから Safari を完全終了する
5. もう一度 1 の数値を見る
```

- **減っていれば** → ②OPFSの掃除は効いている。残りは①だけ
- **減らなければ** → 掃除が走っていない。`app.js` の `opfsSweep()` が
  例外を握りつぶしていないか、Web Locks が取れずに保守モードへ落ちていないかを疑う
  （`MC.log` に `opfsSweep(深|保守): N件 約XMB を片付けました` が出る）
- 画面に「◯GB残っています」の帯が出るかも同時に確認する

### 次: ①取り込みコピーに対して、サイト側でできること

コードからは消せませんが、**発生量を減らす**余地はまだあります。未着手です。

1. **リロードのたびに再コピーされる問題**
   `clip.file` が消えるため素材の再選択が必要 → そのたびに +数GB。
   セッション復元の設計を見直せば、再選択の回数を減らせる可能性がある（要調査）
2. **選ぶ本数・サイズを減らす導線**
   4K素材をそのまま3本読ませない。v1.113.7 で「縮小版（プロキシ）」を入れたが、
   これは**取り込んだ後**の話。取り込み自体を減らす案内は無い
3. **案内を出すかどうかは優さんの判断待ち**
   2026-08-06 時点では「案内は出さない」と決めている。
   ただし「Safariを完全終了すると戻ります」の一文は事実なので、
   出す価値があるか再検討の余地はある（**勝手に実装しない。必ず確認する**）

### 未着手: 掃除のタイミング

掃除は **Switcher の起動時にしか走らない**。
MarchinZ の他ページ（TOP・大会動画など）を見ているだけでは走らない。
Switcher を開かずに容量だけ減らしたい、という要望が出たら設計変更が要ります。

## 5. 触るときの注意（過去に踏んだ地雷）

- **`opfsSweep` の入口を `opfsSupported()` に戻さない。**
  あれは Worker probe を含むので、probe が一時失敗した起動で掃除が全く走らなくなる。
  入口は `navigator.storage.getDirectory` の有無だけで判定する（v1.113.6 の教訓）
- **深い掃除の条件から `mz-export-result` を外さない。**
  外すと、書き出し完了〜保存の間に別タブを開いた人の**未保存の完成品が消える**
- **`purgeAll` は書き出し中に走らせない**（`busy` を返す実装を維持する）
- **診断の数値は「出す直前に測り直す」。** 古い値を握ったまま表示すると、
  対策の効果判定そのものが嘘になる
- 検証は **代入でなく操作で測る**。`navigator.storage.estimate()` を関数から
  呼んで満足せず、実際にSafariを終了→再訪して iOS の数値を見る
  （`repro-first` / `test-teeth` スキル参照）
