# MarchinZ Switcher 自動カット割アルゴリズム 全仕様

対象バージョン: **v1.91.0**（2026-08-04 / DCIレビュー ＋ ヒアリング回答 ＋ 出番を控えるカメラ 反映後）

この文書は「いま実際に動いているコード」をそのまま書き起こしたもの。
レビューで詰めるための資料なので、**意図ではなく実装を書く**。
数値はすべてコードの定数そのままで、単位は秒・0〜1のスコア。

該当ファイル:

```
tools/switcher/js/beats.js      拍・BPM
tools/switcher/js/sections.js   区間の性格(7指標)
tools/switcher/js/salute.js     演奏開始・終了の検出
tools/switcher/js/visual.js     映像の解析・失格判定・ショット種
tools/switcher/js/director.js   カット割り本体(この文書の主役)
tools/switcher/js/layout.js     カット状態→描画(ディゾルブの混色)
```

---

## 0. 全体の流れ

```
素材(動画N本 + 音声1本)
  │
  ├─① 音の解析 ─────────────────────────────────
  │    beats.analyze     拍グリッド・BPM
  │    sections.analyze  0.5秒ごとの特徴量タイムライン
  │    salute.detect     演奏開始(musicStart)・終了(musicEnd)
  │    director._impacts 衝撃(音圧の急上昇)の時刻 ★v1.88.0で新設
  │
  ├─② 映像の解析(カメラごと) ────────────────────
  │    visual.analyzeClip  ブレ・パン・顔・動き・鮮鋭度をサンプリング
  │    visual._finalize    カメラの「性格」を推定(操作/俯瞰固定/定点)
  │
  └─③ カット割り ───────────────────────────────
       director.generate  時間軸を頭から舐めて、区間ごとに
                          「長さ」→「カメラ」を決めて cutList を積む

cutList = [{ t, clipId, trans:"cut"|"dissolve", dur }]  ← 昇順・セグメント開始
                          ↓
       layout.cutAt(t) が再生・書き出しの両方で同じ配列を読む
```

**決定的（ランダム性ゼロ）**。同じ素材・同じ設定なら必ず同じ結果になる。

## 1. 音の解析

### 1-1. 拍とBPM（beats.js）

```
入力   8kHzモノPCM(同期用に抽出済みのものを再利用)
窓     512サンプル(64ms) / ホップ128サンプル(16ms)
手順   FFT → スペクトラルフラックス(正の差分の総和) → 包絡 env[]
       → 自己相関でテンポ(60〜200BPM) → 拍グリッド beats[]
出力   { bpm, period(1拍の秒), beats[], env[], hopSec }
```

### 1-2. 小節の頭（director._grid）

拍を `MC.S.beatsPerBar`（既定4）ごとに区切り、**どの位相を小節頭にすると
オンセット包絡の合計が最大になるか**を全位相試して決める。

```
for ph in 0..beatsPerBar-1:
    s = Σ env[拍 ph, ph+bpb, ph+2bpb, ...]
小節頭 = s が最大の ph
```

拍が4本未満なら「範囲内に拍が足りません」で中止。

### 1-3. カット点のスナップ（director._snap / _snapBeat）

```
_snap(目標時刻, 下限)     小節頭を優先。ただし目標から1.5拍以上ズレるなら拍で妥協
_snapBeat(目標時刻, 下限) 拍だけを見る ★衝撃の2拍前という拍単位の狙いを鈍らせないため
```

### 1-4. 区間の性格（sections.js）

0.5秒ホップ・1.0秒窓で特徴量を作り、区間 [g0,g1] の平均から7つのスコアを出す。

| 生の特徴量 | 中身 |
|---|---|
| `rms` | 音圧 |
| `onset` | オンセット密度（beats の env を0.5秒ビンへ集約） |
| `centroid` | スペクトル重心（高い＝マレット・シンバル寄り） |
| `harm` | 調波性（自己相関の最大／ゼロラグ。高い＝音程もの） |
| `bpmLocal` | 12秒窓・4秒ホップの局所テンポ |

正規化はすべて**パーセンタイル基準**（曲ごとに自動で目盛りが合う）。

```
dyn    = norm(rms,      rmsLo(15%),  rmsHi(90%))     音圧 0..1
dens   = norm(onset,    onLo(20%),   onHi(90%))      密度 0..1
bright = norm(centroid, cenMed(50%), cenHi(85%))     明るさ 0..1
```

そこから8指標:

```
quiet      = 1 - dyn
solo       = (1-dyn) × harm × (1 - dens×0.5)
soli       = harm × max(0, 1-|dyn-0.5|×1.6) × (1 - dens×0.4)   dyn 0.5 で山になる
feature    = max(solo, soli)          「誰かが抜かれている」
percussion = dens × (1-harm) × min(1, dyn+0.3)
pit        = bright × harm × dens
tutti      = dyn                       音圧そのもの（見どころ候補の「大盛り上がり」用）
full       = dyn × (1 - 0.5×harm)      ★全奏らしさ（カット割の判断用）
```

> **`tutti` と `full` を分けている理由**（2026-08-04）
> 「全奏は絶対に引き」を音量だけで決めると、**フォルテのソロ**が全奏と同じ点に
> なり、いちばん寄りで見せたい聴かせどころを引きにしてしまう。
> 厚みの手がかりは調波性（harm）── 単独楽器は自己相関のピークが高く、
> 多数の音程＋打楽器が重なるほど下がる。
>
> ```
> フル(音圧.95 調波.30)           → full 0.81  → 引きに限定
> フォルテのソロ(音圧.95 調波.80) → full 0.57  → 限定しない
> ```
>
> `tutti`（音圧）のほうは**見どころ候補の「大盛り上がり」**が使う。
> 「いちばん大きい瞬間＝盛り上がり」で正しいので意味を変えない。
> 共用したら候補の並びが壊れた（QAが検出）。

### 1-5. 演奏開始・終了（salute.js）

```
RMS包絡(100msホップ→1秒平滑)で
  「5秒以上の静けさ(T_low未満)のあと、3秒以上続く高エネルギー(T_high超)」
  → その立ち上がりを musicStart とする
トリムIN = musicStart − 8秒(前振り。サリュートが映るように)
トリムOUT = musicEnd + 10秒
```

検出失敗は静かに諦める（カット割りは続行する）。

### 1-6. 衝撃の検出（director._impacts）★v1.88.0で新設

```
定数  IMPACT_HIGH 0.62   この音圧に達していなければ衝撃と呼ばない
      IMPACT_RISE 0.22   直前3点(1.5秒)の平均からの上げ幅
      IMPACT_GAP  4.0    これより近い衝撃はまとめる(秒)

for i in 3..n-1:
    now = dyn(i)
    if now < IMPACT_HIGH:                 skip
    before = (dyn(i-1)+dyn(i-2)+dyn(i-3)) / 3
    if now - before < IMPACT_RISE:        skip
    t = S.t[i] + offset - 0.25            ← 1秒窓の中央時刻なので遅れを戻す
    t = 最寄りの拍へスナップ(1拍以内なら)
    直前の衝撃から IMPACT_GAP 未満なら捨てる
```

### 1-7. 楽章・セクションの切れ目（director._breaks）★v1.90.0で新設

ショウは1曲ではなく複数の楽章で、切れ目は場面転換そのもの。
寄りのまま通過すると、見ている人は「まだ同じ場面」だと思い続ける。

```
定数  BREAK_LOW       0.30   これ未満を「静けさ」とみなす
      BREAK_HIGH      0.50   ここまで戻ったら「また始まった」
      BREAK_MIN_SEC   1.2    静けさがこの秒数続いて初めて切れ目
      BREAK_BPM_RATIO 0.18   局所BPMがこの割合以上変わったら切れ目
      BREAK_GAP       10.0   近すぎる切れ目はまとめる(秒)

① 静けさの谷 … BREAK_LOW 未満が BREAK_MIN_SEC 以上続き、
                そのあと BREAK_HIGH を超えて戻った瞬間
② テンポの変化 … 隣り合う局所BPMが BREAK_BPM_RATIO 以上変わった瞬間
→ 小節頭へ寄せ、BREAK_GAP 未満のものはまとめる
```

衝撃（1-6）が「音の瞬間」を見るのに対し、こちらは**曲の構造**を見ている。

> **詰めどころ**: しきい値は合成音で決めた値。実素材で拾いすぎ／拾わなすぎの
> 検証がまだ。窓中央の遅れ0.25秒は拍スナップで吸収する前提だが、
> 速いテンポ（1拍0.4秒以下）では半拍を超えて外す可能性がある。

## 2. 映像の解析（visual.js）

### 2-1. 1区間あたりの指標

```
shakeP75     グローバル動きの75パーセンタイル(手ブレ・パンの量)
shakeCamP75  被写体の動きを除いたカメラ自身のブレ
flipRatio    動きの向きが反転する割合
panRatio     方向のそろった動きの割合
act          動いている領域の割合
actNear      前後±数秒の act(隊形が決まって静止した瞬間の救済に使う)
moE          動きのエネルギー
nF / maxF    顔の数 / いちばん大きい顔の画面高に対する比
sharpMean / sharpMed  鮮鋭度の平均・クリップ全体の中央値
operated / settled    操作カメラか / 振り終わって据わっているか
```

### 2-2. 失格（絶対条件・上から順に判定）

| 順 | 条件 | 理由の文字列 |
|---|---|---|
| 1 | `shakeP75 > 0.28` | 急パン・激ブレ |
| 2 | `shakeCamP75 > 0.11` | 手ブレ |
| 3 | `sharpMed > 40 && sharpMean < sharpMed × 0.30` | フォーカス外れ |
| 4 | `panRatio > 0.50 && shakeP75 > 0.05` | カメラを振っている |
| 5 | 顔0 かつ `act < 0.12` かつ `actNear < 0.12` | 人が写っていない |

失格は**採点より上**。スコアは −1000 されるだけでなく、後述のガードも
失格カメラへは切り替えない。

### 2-3. ショット種スコア（shotScores）

顔が取れているとき:

```
close = clamp((maxF - 0.09) / 0.14)                        顔が大きい = 寄り
group = clamp((nF-2)/3) × clamp((14-nF)/7)
        × (0.035 < maxF < 0.20 ? 1 : 0.5)                  3〜10人規模
wide  = nF===0 ? 0.8
        : clamp((0.16 - maxF) / 0.11) × (nF>=6 ? 1 : 0.7)  顔が小さい = 引き
ensemble = min(1, act×1.6) × min(1, moE×12)                同期した大きな動き
```

顔検出が効かないとき（`faceOK` false または `nF < 0`）:

```
wide  = min(1, 0.35 + act×0.8)
close = max(0, 0.55 - act)
group = 0.3
```

役割タグを人が指定していれば上書き（自動判定の誤りに人が勝つ）:

```
role==="wide"  → wide  = max(wide, 0.8)
role==="close" → close = max(close, 0.7)
```

### 2-4. カメラの性格（_finalize・クリップ全体で1回）

```
movingFrac    |dx|>=2px かつ act<0.55 のサンプルの割合
operated      movingFrac > 0.15                    手持ち・ジンバル・人が操作
overheadFixed サンプル3本以上 かつ !operated
              かつ shakeMed <= 0.02 かつ actMed >= 0.25   俯瞰・定点の引き
staticScene   サンプル3本以上 かつ !operated
              かつ actMed < 0.05 かつ moEMed < 0.012      ほとんど何も動かない定点
hotCells      6×4=24セルのうち「4分の1以上のサンプルで動いた」セルの数
staticSubject サンプル3本以上 かつ !operated
              かつ 0 < hotCells <= 8   ★その場で動くだけの定点(v1.91.0)
```

> **`staticScene` と `staticSubject` の違い**（2026-08-04）
> `staticScene` は「ほとんど何も動かない」しか捕まえない。腕を振り続ける
> ドラムメジャーや、マレットが動くフロントピットはすり抜けていた
> （2026-08-03 に −0.40 を入れて以来、実素材では一度も効いていなかった疑い）。
> `staticSubject` は**動く場所が固定されているか**を見る ── 対象のドリル・MMが
> 無いカメラは、毎回おなじ数個のセルだけが動く。
>
> セルの割合（act）ではなく**位置**を見る理由: 引きで隊形全体が動く画は
> act が大きいが動きの中心は画面中央のままで、中心だけを見ると
> 「動いていない」と誤読する。どのセルが動いたかを数えれば取り違えない。

> サンプル3本未満のクリップには性格を付けない（「解析できなかった」を
> 「動きのない定点」と読み替えないため）。

## 3. カット割り本体（director.generate）

### 3-1. 切替頻度のレベル（LEVELS）

ユーザーが「少なめ／おすすめ／多め」から選ぶ。**おすすめが既定**。

| | base | min | max | sameSec | interleave | 引き(base/min/max) | 寄り(base/min/max) |
|---|---|---|---|---|---|---|---|
| 1 少なめ | 5.0 | 3.5 | 7.0 | 8.0 | 2 | 6.5 / 5.0 / 8.0 | 4.0 / 3.5 / 5.0 |
| 2 おすすめ | 3.0 | 2.0 | 4.0 | 5.0 | 3 | 5.0 / 4.0 / 6.0 | 2.8 / 2.0 / 4.0 |
| 3 多め | 2.4 | 1.8 | 3.0 | 4.0 | 4 | 3.6 / 3.0 / 4.5 | 2.2 / 1.8 / 3.0 |

- `sameSec` = 同じカメラが**連続して**オンエアできる秒数の上限
- `interleave` = 何ショットに1回は引きを織り込むか

### 3-2. メインループ

```
t = トリムIN
while t < トリムOUT - L.min:

  ┌─ A. この区間の「種」を決める(カメラを選ぶ前) ──────────
  │   probe = classify(t, t+L.base)          いま分かる音の性格
  │   isOpening  = musicStart != null && t < musicStart - 0.5
  │   probeFeat  = probe.feature > 0.45
  │
  │   ① 衝撃の2拍前に座るか
  │      impAt  = t より後の最初の衝撃
  │      seatAt = impAt - 2拍
  │      seatWide = (seatAt <= t + L.min)     もう座る時刻 → この回が引き
  │   ② サリュート直後の1カット目か
  │      saluteWide = 未使用 && t >= musicStart - 0.25
  │   ③ 全奏か
  │      tuttiWide = probe.full >= 0.7          ★音圧×厚み
  │   ④ 楽章・セクションの切れ目か
  │      breakWide = 切れ目がこの区間の頭にある
  │
  │   forceWide = isOpening ? null
  │             : seatWide   ? "衝撃の2拍前"
  │             : saluteWide ? "サリュート直後"
  │             : breakWide  ? "楽章の切れ目"
  │             : tuttiWide  ? "全奏" : null
  │
  ├─ B. 長さを決める ────────────────────────────
  │   wideTurn = forceWide があるか、または
  │              (!isOpening && !probeFeat && segsSinceWide >= interleave)
  │   R = wideTurn ? L.wide : probeFeat ? L.close : L
  │
  │   mod  = clamp(1.3 - 0.5×probe.dyn - 0.3×tempoN, 0.6, 1.5)
  │          tempoN = clamp((bpm-90)/60, 0, 1)      速い・大きい → 短く
  │   modR = wideTurn ? 1 + (mod-1)×0.4 : mod       ★引きは効きを4割に薄める
  │   target = clamp(R.base × modR, R.min, R.max)
  │
  │   tNext = _snap(t + target, t + R.min)
  │   if tNext - t > R.max + 1.0:  tNext = t + R.max     ソフト上限
  │
  │   ⑤-0 演奏開始／楽章の切れ目そのものにカットを置く
  │   ⑤   衝撃に間に合わせる
  │        座る時刻がまだ先 → そこでちょうど切る(次の区間が座る回になる)
  │        もう座っている   → 衝撃+1拍まで引っぱる
  │
  ├─ C. カメラを選ぶ ────────────────────────────
  │   cls = classify(t, tNext)
  │   ranked = _rank(t, tNext, cls, ctx)      ← 3-3
  │   top = ranked[0]
  │
  │   失格しか無い区間 → 直前のカットをここまで延長して continue
  │                      (「振っている絵は絶対に入れない」が時間上限より強い)
  │
  ├─ D. 2枚のガード(失格でないときだけ) ──────────────
  │   ① 飢餓ガード                            ← 3-4
  │   ② 連続上限                              ← 3-5
  │
  ├─ E. トランジション ──────────────────────────
  │   slow  = cls.bpm < 92
  │   quiet = cls.quiet > 0.55
  │   if (slow || quiet) && 冒頭でない:
  │       trans = "dissolve"
  │       dur = clamp((tNext-t)/3, 1.0, 2.0)、かつ ショット長×0.6 を超えない
  │
  └─ F. 文脈を更新して t = tNext
```

末尾が1.5秒未満なら1つ前へ統合する。

### 3-3. カメラの採点（_rank）

**候補プール**（黒画面の混入を防ぐ3段構え）:

```
1) 区間を丸ごとカバーするカメラ
2) 無ければ 区間の中点をカバーするカメラ
3) それも無ければ 重なりが最大(同率なら距離が最小)の1台だけ
```

**望むショット種の重み**:

```
オープニング(演奏開始前)  wClose 1.0 / wGroup 0.1 / wWide 0.4   DM・サリュート最優先
それ以外                  wClose = 0.30 + 0.95 × feature
                          wGroup = 0.25 + 0.60 × percussion
                          wWide  = 0.25 + 0.45 × full    ★音圧×厚み
                          feature > 0.45 なら wWide ×= 0.5      聴かせどころで引きに逃げない
cls が無い                0.35 / 0.30 / 0.35

引きの織り込み圧力  pw = segsSinceWide / interleave
                    wWide += (pw >= 1 ? 1.0 : 0.5 × pw)
```

**1台あたりのスコア（全項目）**:

```
  失格                          −1000
+ wClose×close + wGroup×group + wWide×wide
+ ensemble × 0.3 × wide                       同期した大きな動きは引きで
+ ピット役 : ピット区間なら +1.2 / それ以外の区間では −0.35
             (ピット区間 = !opening && cls.pit > 0.45 && ピット役のカメラが居る)
+ 出番の希望(素材ごと)  少なめ −0.35 / おまかせ 0 / 多め +0.45
+ 俯瞰固定 +0.15
+ 出番を控えるカメラ −0.40（staticScene または staticSubject）
+ 画質  +0.1 × min(1.2, sharpMean / sharpMed)
+ 操作カメラが据わっている  +0.12
    さらに feature > 0.35 なら  +0.9 × feature × close
− 直前と同じカメラ  −0.90
− 2つ前と同じカメラ −0.25
+ 出番が空いた分   +0.06 × min(8, 前に出てからのショット数)   最大 +0.48
− 直前と似すぎた画  最大 −0.55   ★ジャンプカット防止(v1.90.0)
    隔たり d = |寄り差| + |引き差| + min(1, |人数差|/4)
    d < 0.35 のとき、近いほど強く減点。**失格にはしない**
```

> **なぜ「似かた」で見るのか**: 本来はカメラの位置関係（同じ側の2台を
> 続けない＝軸越えを避ける）で判断すべきだが、いまツールは各カメラが
> どこから撮っているかを知らない。同じ側のカメラは画も似るので、
> 画の似かたを位置の代用にしている。**位置タグを入れれば本式にできる。**
> 実測: そっくり同士の切り替えが 9回 → 1回。
> 失格にしないのは、3台とも似た引きという素材が普通にあり、
> 失格にすると切り替えそのものが止まるため。

**ハード規則（候補を引きだけに絞る）**:

```
hardWide = !opening && ( forceWide があるか
                       || (!featuring && segsSinceWide >= interleave) )
    ※ featuring = cls.feature > 0.45
    ※ forceWide(全奏・衝撃の2拍前・サリュート直後)は featuring の例外も貫く

hardWide なら、失格でない引きのカメラだけを返す。
1台も居なければ通常の順位に戻す(カット割りを止めない)。
```

### 3-4. 飢餓ガード（出番の最低保証）

```
STARVE = 4        4ショット出ていないカメラが居たら、採点に関係なく次に出す
                  該当が複数なら採点順で最良の1台
                  実際に経過したショット数で数える(sinceUse の初期値99を素で読まない)

★ソロ・ソリ中は繰り延べる(v1.88.0)
  STARVE_DEFER = 2   ただし待てるのは2ショットまで

★出番を控えるカメラは間隔を伸ばす(v1.91.0)
  QUIET_STARVE_MULT = 2   その camera だけ STARVE を 4→8 にする
  対象 = freq "少なめ" / staticScene / staticSubject
```

> **なぜ減点だけでは足りなかったか**（2026-08-04 優さん指示で判明）
> 減点（STATIC_BIAS −0.40 / FREQ_BIAS.less −0.35）は**採点の話**でしかなく、
> 飢餓ガードは採点を無視して STARVE ショットごとに強制的に出す。
> つまり「少なめ」と指定しても出番の**回数**は他と変わっていなかった。
> 控えたいカメラは、飢餓とみなすまでの間隔そのものを伸ばす必要がある。
>
> 実測（3カメラ・29カット）: 素のまま 9回 → 控えめ 4回。
> 飢餓の間隔を伸ばさないと 6回止まり。**出番ゼロにはしない**（3台とも出る）。

> **なぜ上限が要るか**: 2026-08-02 の実機で「3本入れたのに2台しか出ない」が
> 起きている。原因は採点の構造で、上位2台は「直前 −0.9 / 2つ前 −0.25」を
> 交互に払いながら回るが、3台目は常に**その区間の勝者**（罰を払っていない側）に
> 勝たねばならず、登場間隔ボーナス +0.48 では届かない。
> `feature` が曲じゅう高止まりする実素材があるため、ソロ中の繰り延べを
> 無条件にすると、この不具合がそのまま戻る（QAの変異テストで実際に戻ることを確認済み）。

実測（QAの3カメラ固定素材・29カット）:

```
繰り延べ 0回 → 3台目が5回出る
         2回 → 4回     ← 採用
         3回 → 3回
      無制限 → 2台になる(不具合が再現)
```

### 3-5. 連続上限

```
時間が主・回数は従
  同じカメラの連続オンエアが L.sameSec を超える見込み  → 別カメラへ強制切替
  または MAX_RUN(3ショット)に達した                    → 同上
失格でない別カメラが1台も無ければ切り替えない
```

### 3-6. 描画（layout.cutAt）

```
ディゾルブ中(t - カット開始 < dur)は
  cur = このカット / prev = 1つ前のカット / blend = (t - カット開始) / dur
それ以外は blend = 1(1台だけ)
```

## 5. 分かっている弱点（レビューで叩いてほしい所）

1. ~~`tutti` は音圧そのもの~~ → **v1.90.0 で `full`（音圧×厚み）へ分離済み。**

2. **`TH_HOT_CELLS`（8/24）は合成素材で決めた値**。実素材での検証がまだ。
   書き出しログに「出番を控えるカメラ … 動くセルN/24」を出しているので、
   そこが調整の根拠になる。

3. **ソリストが本当にフレームに入っているかを見ていない**（P4・未実装）。
   `feature`（音）が高い区間で `close`（顔が大きい）カメラを優先しているだけで、
   そのカメラが**その奏者**を抜いている保証はない。楽器検出が要る。

3. **衝撃のしきい値が合成音基準**。実素材での検証がまだ。
   書き出しログに `衝撃N箇所` を出しているので、そこが判断材料。

4. **引きの長さ 4〜6秒は「切替頻度レベルの中」の値**。
   レビューの提案は 4〜8秒だが、2026-08-03 の「4秒以上は同じのにしない」と
   衝突するため、レベルに応じてスケールさせている（少なめなら5〜8秒）。

5. **ディゾルブは局所BPMと静かさだけで決めている**。
   v1.90.0 で楽章の切れ目が取れるようになったので、
   「バラード楽章の中だけ」に絞れる（未実装）。

6. **カメラの空間関係を持っていない**。どのカメラがどの向きから撮っているかを
   知らないので、イマジナリーライン（軸越え）を正確には止められない。
   **v1.90.0 で簡易版（画の似かたで代用）を入れたが、本式には位置タグが要る。**
   → `docs/SWITCHER_CRITERIA_HEARING.md` 回答A

7. **ソロ中でも `sameSec` は効く**。おすすめ（5秒）では、抜いている画を
   どんなに見せたくても5秒で切れる。

8. **カット点は常に拍・小節に乗る**。フレーズの終わりや息継ぎでは切れない
   （音楽の区切りとしては小節頭を代理に使っている）。
